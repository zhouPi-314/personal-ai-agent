# Web 维护界面设计

> 定位：**运维台，不是聊天入口**。聊天仍然只在 QQ 里进行。
> 这与"不开发网页聊天"的边界一致——本界面只给所有者本人看数据和改配置。

## 为什么要做

系统跑起来以后，有三类事情在 QQ 里做不了：

1. 看**现在是什么状态**（路由走了哪条、今天花了多少 token）
2. 看**它为什么这么回**（这条消息用的哪条记忆、哪个模型）
3. 做**需要谨慎的操作**（撤销记忆、审批任务、改人格卡）

## 页面

| 页面 | 内容 | 优先级 |
|---|---|---|
| 概览 | 服务健康、路由状态（primary / fallback）、今日 token 与费用、任务队列长度 | P0 |
| 会话 | 按人/时间浏览消息，每条标注「谁生成的」 | P0 |
| 记忆 | 列表、来源消息、置信度、撤销按钮 | P0 |
| 任务 | 状态机、执行日志、待审批项 | P1 |
| 审计 | 只追加的操作记录，不可编辑 | P1 |
| 设置 | 供应商与模型、人格卡版本、设备授权 | P1 |

## 关键设计

**每条消息显示生成来源。** 混合路由下，这是判断"为什么今天说话不像昨天"的唯一线索：

```
14:32  我：今天好累
14:32  她：那就早点睡        [本地·DSH]
14:35  我：睡不着
14:35  她：数羊吧            [云端·DeepSeek]
```

**撤销记忆要显示影响面。** 点撤销前告诉用户：这条记忆被引用过几次、最近一次是什么时候。

**"测试连接"必须真打一次请求。** 返回真实延迟与模型名，不做假成功。

## 技术选型

- 前端：Vue 3 + TypeScript + Vite，单页应用，构建产物由 FastAPI 托管
- 通信：REST 拉数据，SSE 推实时事件（任务状态、新消息）
- 鉴权：单用户本地令牌（`PAA_UI_TOKEN`），只监听 `127.0.0.1`
- 不引入组件库全家桶，保持依赖最小

## 明确不做

- 不做网页聊天输入框（聊天入口只有 QQ）
- 不做多用户与权限体系
- 不做公网暴露；远程维护走 Tailscale
- 不做移动端适配（手机用 QQ 就够）

## 落地时机

阶段 4。界面是数据的投影，先有消息、任务、审计数据，界面才有东西可显示。
现在做只能摆一堆空表格。

## 已实现的 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 消息/记忆/任务/审计条数 |
| GET | `/api/messages?limit&before_id` | 消息列表（倒序、游标分页） |
| GET | `/api/memories?kind&include_revoked` | 记忆列表 |
| POST | `/api/memories/{id}/revoke` | 撤销一条记忆 |
| GET | `/api/tasks` | 任务列表 |
| GET | `/api/audit` | 审计记录 |

配置 `PAA_UI_TOKEN` 后，除 `/api/status` 外的接口都需要请求头 `X-PAA-Token`。
