# DSH Companion（DSHC）项目设计构想

> **归档说明（2026-10-19）**：本文原属编号 03 项目，现集中存放于
> `<项目根>`；PAA 为该项目的旧代号。

> 中文名称：DSH 灵犀  
> 英文全称：DeepSeek Harness Companion  
> 项目定位：围绕 DeepSeek Harness（DSH）构建的私人聊天、长期记忆与云端—Windows 协同系统  
> 文档性质：产品与架构构想（非开发任务书）  
> 版本：v1.0｜2026-10-19

## 1. 项目愿景

打造一个以 **DeepSeek Harness 为唯一 AI 核心**的私人智能体：通过独立 QQ 小号与用户实时交流，延续长期记忆，接收并管理工作任务；通过阿里云服务器保存状态和协调工作，通过 Windows 电脑上的现有 DSH 执行需要本地工具的任务。

项目应具备可持续维护、低成本运行、安全可控、模块化开源及跨设备迁移能力。它是 DSH 的伴随系统，不是另一个大模型，也不是多模型聚合平台。

## 2. 范围与非目标

### 纳入范围
- QQ 小号作为**唯一日常聊天入口**：文本聊天、陪伴交流、任务指令、结果通知与审批提醒。
- DSH 作为唯一 AI 引擎，优先复用 Windows 已有安装与配置。
- 云端长期记忆、会话连续性、工作项目上下文、任务状态持久化。
- 云端与 Windows 安全同步，支持电脑离线时任务排队、上线后恢复。
- 独立的本地安全配置窗口，管理账号连接、授权、凭据状态及日志。
- 开源友好的配置模板、安装迁移说明、备份与恢复方案。

### 暂不纳入
- 微信接入。
- 网页聊天客户端（管理配置窗口不属于聊天客户端）。
- 其他 AI 模型、供应商适配或多模型切换。
- 云服务器本地部署大模型权重或 GPU 推理。
- 未经授权的全自动高权限电脑控制。

## 3. 总体架构

```text
用户 QQ 主账号
    │ 文字聊天 / 任务 / 审批请求
    ▼
独立 QQ 小号
    │
QQ Gateway（非官方普通账号方案需评估风险）
    │
    ▼
阿里云 ECS：DSHC Cloud
  ├─ 消息路由与身份校验
  ├─ 会话与长期记忆
  ├─ 任务队列 / 状态机 / 定时提醒
  ├─ 权限审批与审计
  └─ DSH 调用协调器
           │ 安全加密通信
           ▼
Windows：DSHC Desktop
  ├─ 已配置的 DeepSeek Harness（唯一 AI 核心）
  ├─ 授权工作区内的工具与项目任务
  ├─ Git / Codex / Python / 浏览器等执行能力
  └─ 本地 Security Center
```

**重要能力边界：** 若云端只有消息网关、记忆和队列，而 DSH 只运行在 Windows，则电脑关机后**无法保证 AI 继续生成聊天回复**。全天候聊天必须另行验证云端可独立运行的 DSH 或其受支持的远程调用方式，并评估 2GB 内存、费用及接入兼容性；验证前不承诺 24 小时完整聊天。

## 4. 核心子系统

### 4.1 QQ Gateway
- 负责消息接收、发送、去重、断线恢复、频率限制与状态告警。
- 将聊天内容转为标准内部事件，不允许直接把 QQ 消息拼接成系统命令。
- 普通 QQ 小号接入可能依赖非官方实现，存在登录限制、协议变更、账号风控和服务条款风险；应与核心逻辑解耦，并保留停用及替换能力。
- QQ 账号及登录会话属于私密部署数据，绝不进入开源仓库。

### 4.2 DSH Core Adapter
- 仅连接 DeepSeek Harness，不引入其他 AI 引擎。
- 先核实本机 DSH 实际支持的 CLI、接口、会话与工具机制，再定义适配协议。
- 复用现有配置，不复制、不打印、不提交 API Key 或会话凭据。
- 对 DSH 升级带来的参数变化进行兼容性检查和错误隔离。

### 4.3 记忆系统
- **会话记忆**：近期对话与上下文摘要。
- **长期个人记忆**：经用户允许保留的偏好、重要事件、沟通习惯。
- **项目记忆**：任务目标、计划、决策、代码仓库引用、进度和结果。
- **系统记忆**：设备、权限和运行状态；与私人聊天内容隔离。
- 支持记忆查看、纠错、删除、导出、保留期限和备份恢复。
- 情感陪伴应保持自然与尊重，不虚构现实身份、意识或无法实现的承诺。

### 4.4 任务协同
- 任务状态建议：待确认 → 排队 → 执行中 → 待审批 / 已完成 / 失败 / 已取消。
- 电脑离线时保存任务；上线后根据权限和有效期决定是否继续。
- 高风险操作采用明确审批，不把单条 QQ 文本视为充分的强认证。
- 支持超时、重试上限、幂等执行、暂停、取消、结果回传和审计。

### 4.5 Security Center
- **独立本地配置窗口**，不是网页聊天工具。
- 配置 QQ 连接、DSH 状态、服务器地址、设备授权、工作区权限、备份及日志。
- 凭据优先存储在操作系统安全凭据库或受保护的服务端密钥存储中；界面不回显完整秘密。
- 默认禁止公网访问管理端口；远程管理须单独启用身份验证。

## 5. 云端与本地的职责分工

| 能力 | 阿里云 Cloud | Windows Desktop |
|---|---|---|
| QQ 消息连接 | 优先部署，需验证可行性 | 可用于开发测试 |
| 长期记忆与任务状态 | 主存储 | 必要缓存 |
| DSH 推理与工具调用 | 仅在资源与接口验证通过后启用 | 优先复用已有环境 |
| 本地文件、开发工具、仿真 | 不承担 | 主要执行端 |
| 定时通知和队列 | 负责 | 执行可用的任务 |
| 私密凭据配置 | 服务端安全存储 | 本地 Security Center |

现有阿里云 ECS 基线：**成都、2 vCPU / 2GB RAM、Ubuntu 24.04、40GiB 系统盘、3Mbps 按流量计费**。它适合轻量协调服务，但不能未经压测就认定能同时稳定运行 QQ 接入、数据库及完整 DSH。初期避免不必要的常驻服务，按资源测量决定是否增加组件。

## 6. 安全与隐私原则

1. **默认最小权限**：仅允许授权目录和工具；删除、安装软件、系统设置、外发私人文件等须确认。
2. **凭据隔离**：QQ 密码、登录会话、DSH API Key、SSH 私钥、数据库密码不进入源码、日志或 GitHub。
3. **端口最小暴露**：数据库不开放公网；SSH 优先密钥登录与可信来源限制；云端与 Windows 使用加密连接。
4. **防提示词注入**：QQ 消息、网页和文件均视为不可信输入，不能覆盖工具权限策略。
5. **审计可控**：记录任务类型、授权与执行结果，日志脱敏，允许按策略清理。
6. **开源安全**：提供 `.env.example`、`.gitignore`、密钥扫描、漏洞报告与安全说明；发布前审查历史提交。
7. **费用可控**：监测公网流量、存储与 DSH 调用费用；设置预警，但不将预警误认为硬性费用上限。

## 7. 通用性与可移植性

- QQ 账号、服务器地域、IP、数据库地址、Windows 路径等均由部署者自行配置，不硬编码。
- 服务组件接口清晰，可分别部署和升级；配置与业务数据分离。
- 采用数据库迁移、结构化配置、可恢复备份和版本兼容策略。
- 优先支持 Windows + Linux 云端的组合；未来可迁移到其他云厂商。
- DSH 为必需依赖；项目不承诺兼容其他模型。

## 8. 用户体验示例（概念）

**陪伴交流**：用户通过 QQ 发送日常消息；系统在用户授权的记忆范围内保持对话连续性。

**工作协作**：用户发送“检查某项目的测试结果”；云端创建任务，Windows 在线且获授权时由 DSH 处理，并将进度和结果发回 QQ。

**离线处理**：电脑离线时云端记录待办，告知当前无法执行本地操作；电脑上线后按策略恢复。

**审批**：涉及敏感文件或高风险操作时，系统请求明确确认，并通过可信的额外认证机制完成审批。

## 9. 分阶段构想（仅规划，不授权开发）

- **阶段 A：可行性验证**：确认 DSH 受支持接口、QQ 接入的运行环境与风险、云端资源边界。
- **阶段 B：最小闭环**：QQ 文本消息 ↔ DSH ↔ 回复；建立基础安全和任务状态。
- **阶段 C：长期记忆**：会话与项目记忆、导出删除、备份恢复。
- **阶段 D：云端—Windows 协同**：离线队列、授权执行、任务结果与审批。
- **阶段 E：增强能力**：定时提醒、图片理解、语音交互、复杂任务管理等，在稳定性与预算允许时推进。

各阶段须独立验收，不能因本构想文档而自动开始实施。

## 10. 成功标准与关键风险

**成功标准**：QQ 交互可用、记忆连续且可管理、DSH 能在明确权限内执行任务、电脑离线状态透明、敏感信息不外泄、系统能迁移和恢复、成本可观察。

**关键风险**：非官方 QQ 接入稳定性与账号风控；DSH 实际接口兼容性；2GB 云服务器资源限制；公网流量及模型调用费用；远程任务执行的安全边界。
